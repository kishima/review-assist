# マーカーと、記法を畳む編集画面（0.2・0.3）

2026-10-17。著者「なるべく印刷時の見た目に近い状態で、それを編集しつつ、AIにダブルチェックしてほしい部分や後で読みたい部分にそれぞれマーカーを付けてあとでまとめて検査おねがいするような機能を持った編集アプリがほしい」「REVIEWの記法が混じった文章を編集するのがつらいので、そこを何とかする方法も考えたい」。本体（Claude）の提案（review-assist を伸ばす、記法はカーソルの近くだけ見せる、マーカーを先に）に著者が同意（2026-10-17「はい、計画書かいて」）。

最初の利用者は `book_mruby3`。締め切りが近いので、**段階 1 だけで使える形にして先に渡す**（0.2.0）。段階 2・3 は 0.3.0。

## 決めたこと

 * **原稿は `.re` のまま。** 変換（Markdown など）はしない。編集画面は `.re` の文字列そのものを編集し、記法を「見せ方」で畳むだけ。保存されるものは手で書いたのと同じ `.re`。理由: 変換の往復で Re:VIEW の書式が落ちる・崩れるのを避ける。
 * **印刷と同じ見た目は目指さない。** 紙面の正は PDF（Re:VIEW → upLaTeX）。編集画面は「紙面に近い」まで。本物を見たいときは既存の「この節を PDF で開く」。理由: LaTeX の組版を HTML で再現するのは割に合わず、見た目の差は PDF で確かめる。
 * **マーカーは原稿に書かない。** 別ファイルに、前後の文脈ごと保存する（下の「マーカーの保存」）。原稿に `#@#` を足すと差分と textlint を汚し、消し忘れると PDF のソースに残る。
 * **AI との受け渡しはファイル。** 拡張は依頼ファイルを書き出し、結果ファイルを読むだけ。AI（Claude Code）を拡張から呼ばない。理由: 拡張に API キーやネットワークを持たせない。著者は Claude Code に「AI チェックして」と言う。
 * **実行時依存を持たない方針（`../design/architecture.md`）の例外を 1 つ作る**: 段階 2 の編集画面に CodeMirror 6 を使う。esbuild で webview 用の 1 ファイルに束ね、`.vsix` に入れる。原稿を書く人に `npm install` を強いない点は変わらない。理由: 日本語の IME、取り消し、検索、範囲の装飾を自前で書くのは割に合わない。拡張本体（`dist/extension.js`）には依存を入れない。
 * 数（色、幅、文字の大きさ、待ち時間など）は `.review-assist.json` の設定に置き、既定値と出どころを `../design/thresholds.md` に書く（`/home/kishima/book/CLAUDE.md` の規則）。

## 段階 1（0.2.0）: マーカーと、まとめて AI に頼む仕組み

今の VS Code のエディタのまま使える。

### 到達点

 * **マーカーの種類**は設定 `marks.kinds`（`id`、表示名、色）。既定は `ai-check`（AI にダブルチェック）と `read-later`（後で読む）の 2 つ。
 * **付ける・外す**: 範囲を選んでコマンド（「マーカーを付ける: AI チェック」「…: 後で読む」）。メモを 1 行付けられる（空でもよい）。キーバインドの既定は持たず、README に例を書く（著者が選ぶ）。
 * **見せ方**: エディタでは範囲に背景色、行の横（ガター）に印、ホバーにメモと AI の結果。サイドバーに「マーカー」ビュー（種類 → 章 → 項目。クリックで飛ぶ。済み／未済で絞れる）。
 * **マーカーの保存**: ワークスペースの `.review-assist/marks.json`。1 件は `id`、`kind`、`file`、`quote`（選んだ文字列）、`prefix`・`suffix`（前後の数十文字。長さは設定、既定は測って決める）、`line`（目安）、`note`、`created`、`status`（`open`／`done`）。原稿を直したら、`quote` と前後の文脈で位置を探し直す（W3C Web Annotation の TextQuoteSelector と同じ考え方）。見つからないものは「位置を見失った」としてビューに出し、消さない。`.review-assist/` を git に入れるかは本の側で決める（`book_mruby3` では入れない: 個人の作業の印なので。`.gitignore` に足す）。
 * **AI への依頼を書き出す**: コマンド「AI チェックの依頼を書き出す」が、`status: open` の `ai-check` を `.review-assist/ai-check.md` に書く。1 件ごとに id、章とファイルと行、見出しの道筋、選んだ文と前後の段落、メモ。AI が読む手順（何を確かめるか、結果の書き方）は本の側の文書（`book_mruby3/docs/` の該当場所。置き場所は notes の README の目次に従う）に書き、依頼ファイルの先頭からそこを指す。
 * **AI の結果を読む**: AI は `.review-assist/ai-results.json` に id ごとの `verdict`（`ok`／`fix`／`question`）、`comment`、任意の `suggestion`（置き換え案の文字列）を書く。拡張はファイルの変更を見て、ホバーとビューに出す。`suggestion` は「案を当てる」コマンドで原稿に入れられる（当てたら著者が見て「済み」にする。自動で済みにしない）。
 * `src/core/marks.ts`（保存形式、位置の探し直し、依頼の組み立て、結果の読み込み）は VS Code に依存しない層に置き、`node:test` で確かめる。VS Code 層は写すだけ（`architecture.md` の規則）。

### 確認

 * 単体テスト: 位置の探し直し（前後に文を足す、選んだ文の中を直す、段落を移す、消す）、同じ文が 2 か所にあるときに前後の文脈で正しい方を選ぶこと、依頼ファイルの形、結果の読み込み（壊れた JSON、知らない id）。
 * `book_mruby3` の実物の章で、マーカーを付けた原稿に `git log` の過去の修正を当てて、見失う割合を数える（`../verification/` に表で）。
 * 依頼 → AI の結果 → 表示を 1 巡、本体（Claude）が `book_mruby3` で実際にやって、手順の文書を直す。
 * VS Code の実機での確認は著者（Extension Development Host が使えない環境のため）。確かめてほしい操作を README の「確かめ方」に箇条で書く。

## 段階 2（0.3.0）: 記法を畳む編集画面

### 到達点

 * **専用の編集画面**（`CustomTextEditorProvider`、`.re` を「Review Assist で開く」。既定のエディタは変えない。普通のエディタとの切り替えはコマンド 1 つ）。中身は webview の CodeMirror 6。`TextDocument` と双方向に同期し（`WorkspaceEdit`）、保存・取り消し・dirty の印は VS Code のものを使う。
 * **畳み方**（ライブプレビュー）: カーソルがその記法の外にあるとき、記法の印を隠して中身を見た目で表す。カーソルが中に入ったら元の記法を出す。
   * インライン（原稿で多い順）: `@<code>` 等幅、`@<b>` 太字、`@<hidx>` は印ごと隠す（紙面に出ないため。設定で薄く出す）、`@<chap>`／`@<hd>`／`@<table>`／`@<list>`／`@<img>`／`@<fn>` は参照先の題を小さな札で（索引の解決を使う。解決できないものは赤）、`@<embed>` は札（中身は出さない）、`@<br>`、`@<href>`。
   * 行: 見出し（`=`〜`=====`）は大きさを変え、`{label}` は札。`#@#` は薄く。箇条（` * `、` 1. `、` : `）は字下げ。
   * ブロック: `//list`、`//emlist`、`//cmd` は枠と見出し（id とキャプション）、中は等幅。`//table` は表として表示し、セルの中を編集できる（`//tsize` は札）。`//image` は PNG（既存の `imagePreview`）。`//footnote`、`//quote`、`//pagebreak`（線）。
   * 本の原稿で使っているのに表し方を決めていない書式は、記法のまま見せる（壊さない）。どれが残ったかを数えて `../verification/` に書く。
 * **入力の助け**: 選んでショートカットで `@<code>{}`／`@<b>{}` などで囲む（中の `}` と `\` はエスケープ）。`@<chap>{`、`@<hd>{`、`@<list>{`、`@<table>{`、`@<img>{` で候補（既存の索引）。ブロックの雛形の挿入。
 * **段階 1 のマーカーと診断を同じ画面に**: マーカーの背景色、付ける操作、AI の結果。VS Code の診断（この拡張の規則と textlint）も webview に送って波線で出す。
 * パーサは `src/core/parser.ts` を使う（3 つ目の実装を作らない）。webview 側に要る形（範囲と種類の一覧）は `core` で作って送る。

### 確認

 * webview の中身は VS Code 無しでも動く形にし、Playwright（`~/.cache/ms-playwright` の Chromium）で `book_mruby3` の全章を開いて、pageerror 0、畳んだ表示から元の文字列が 1 文字も変わらないこと（読み込んで書き出したら同一）、カーソルを各記法に入れると記法が出ること、を確かめる。
 * 日本語 IME での入力、取り消し、保存は著者の実機で（README の「確かめ方」）。
 * 大きい章（`contents/vm.re` など）を開いて打つときの遅さを測り、`../verification/` に。

## 段階 3（0.3.0）: 紙面に近い見た目

### 到達点

 * 本文の幅、文字の大きさ、行の間、見出し・コード・表の体裁を、本の設定（`config.yml` の `texdocumentclass`、`layouts/`、`sty/` など）から読める分は読み、読めない分は PDF を測って既定値にする（設定で変えられる。出どころは `thresholds.md`）。書体は本と同じものが PC にあればそれ、無ければ近いもの。
 * 見出しの横に PDF のページ番号（既存の `pageIndex`）を出す。PDF が古いとき（原稿の方が新しいとき）は薄く出す。
 * 1 行の長さ、表の幅が紙面からはみ出しそうな所は、段階 2 の診断（既存の `tableWidth`、`maxCodeLineLength`）をそのまま見せる。

### 確認

 * 同じ節を PDF と編集画面で並べた画像を `../verification/` に（改行の位置がどれくらい合うかを数える。合わせ込みはしない）。
