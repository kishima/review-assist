# 2026-09-19 review-assist v0 段階 1・2

計画書 `docs/plans/v0-plan.md` の段階 1（索引・定義へ移動・ホバー・アウトライン・参照切れ）と
段階 2（規則の診断・表の幅）を作った。段階 3（PDF との往復）と段階 4（配布の自動化）は手つかず。

リポジトリは空（`git init` 済み、`main`、コミット無し、`docs/plans/v0-plan.md` だけ）の状態から
始めた。最初の利用者は `book_mruby3`。

## まず原稿を見て、何を解けばいいのかを決める

`book_mruby3` でどんな参照が実際に使われているかを数えた。

```
$ grep -ho '@<[a-z]*>{[^}]*}' contents/*.re sub-article/*.re | sed 's/{.*//' | sort | uniq -c | sort -rn
  11357 @<code>      549 @<b>      315 @<hidx>      282 @<chap>      263 @<hd>
     75 @<list>       67 @<table>   46 @<embed>      24 @<br>        11 @<href>
      7 @<img>         3 @<fn>
```

参照になるのは `chap` `hd` `list` `table` `img` `fn` の 6 つで、`code` や `b` は違う。
`@<hd>` 263 件のうち 261 件が `chap_XXX` という形で、`opcodes` 章の記事の見出しを指している。
そして `=={chap_SEND} SEND、SEND0、…` という見出しの定義は `sub-article/*.re` にあり、
`catalog.yml` が指す `contents/opcodes.re` は `insert.rb` が作る生成物である。
ここが計画書の言う「章 ID と元ファイルの対応づけ（設定 `chapters`）」の理由だと分かった。

最初は「生成物も元ファイルも両方索引すればよい」と考えたが、それだと同じラベルが 2 つになり
「id が二重」の診断が 100 件以上出る。`chapters` で読み替えた章の `catalog.yml` 上のファイルは
**索引から自動で外す**ことにした。設定に `exclude` も足したが、`book_mruby3` では要らない。

## 参照の解決の規則は、推測せずに本家を読む

ここが一番時間を使ったところである。

最初は自分で規則を決めた。「`|` で割って、先頭が章 ID ならその章。章の中ではラベル →
見出しの文字列 → 見出しの道」。`book_mruby3` の現在の原稿ではこれで参照切れ 0 件になり、
一見うまくいった。

計画書の「確認」に「一度直した参照切れを戻すと検出されること」とあるので、
`git log -S` で当該のコミットを探したが、`vm` の「可視性」も `corelib` の「Floatの文字列化」も
見つからない。どうも、あれは `@<hd>` ではなく**地の文で節名を書き間違えた**方（`d42a2d2` の
「節名の引き違い 2 件」）らしく、この拡張が見るものではない。

そこで別の確かめ方にした。`git archive` で過去の木をスクラッチパッドに取り出し（本の
リポジトリには触らない）、`.re` を触ったコミット 60 本に CLI を順に掛けた。13 本で error が出た。
そのうち 11 本が同じ 2 件で、`chapter02.re` の

```
@<hd>{chapter03|chap_LAMBDA|補足}
@<hd>{chapter03|chap_EXCEPT|補足}
```

だった。これは初版（`bcb3a19` "copy from mruby bytecode handbook"）から来ている。初版は Re:VIEW で
組んで実際に本になっているので、**壊れていたのはこちらの規則の方**だろうと疑った。

Re:VIEW 2.5.0 の実装を取ってきて読んだ（`kauplan/review2.5` を使っているので 2.5.0）。

```
$ curl -sL https://raw.githubusercontent.com/kmuto/review/v2.5.0/lib/review/book/index.rb
```

`HeadlineIndex.parse` の中心はここだった。

```ruby
index = m[1].size - 2
...
next unless index >= 0
headlines[index] = m[3].present? ? m[3].strip : m[4].strip
items.push Item.new(headlines.join('|'), indexs.dup, m[4].strip)
```

つまり:

* `index = (= の数) - 2` なので、`=`（章の題）は索引に入らない。`==` が 0 段目
* 各段は「ラベル（`m[3]`）があればラベル、無ければ題（`m[4]`）」
* 鍵は 0 段目からその見出しまでを `|` でつないだもの

`=={chap_LAMBDA} LAMBDA、BLOCK` の下の `=== 補足` の鍵は `chap_LAMBDA|補足` になる。
**初版の参照は正しかった。**

引き方（`Index#[]`）も読んだ。完全一致 → 最後の段が一致するものが複数なら `ambiguous` で
`KeyError` → どれか 1 段が一致する最初のもの、という 3 段構えだった。3 段目があるので
`@<hd>{chap_LAMBDA}`（道の途中）でも引ける。2 段目があるので `@<hd>{補足}` は Re:VIEW の
ビルドを止める。

自分で決めた規則は捨て、`src/core/resolve.ts` を本家の 3 段構えに書き直した。
`Heading` に `indexId`（本家と同じ鍵）を足し、`[column]` の中と題の空の見出しを除く処理も入れた。
書き直したあと、同じ 60 本を掛け直した。

| コミット | 残った検出 | 中身 |
|---|---|---|
| `e374f9e` | 1 件 | `@<hd>{chapter03|chap_ONERR|補足}` |
| `9619ca4` | 2 件 | `@<chap>{chapter06}` |
| 他 58 本 | 0 件 | — |

`chap_ONERR` は、そのコミット自身が記事を `=={chap_EXCEPT}` に改名したときの取り残しだった
（`sub-article/chap3-030-EXCEPT.re:1` が `chap_EXCEPT`）。`chapter06` は当時の `catalog.yml` に
無い。どちらも**本当の参照切れ**で、これが計画書の言う回帰の確認になった。

副産物として「曖昧な参照」（本家が `ambiguous` で落とす形）を error の診断として足した。
現在の `book_mruby3` には 1 件も無い。

ついでに `Index.parse` の `item_type` も読んで、`@<list>` が `//emlist` や `//cmd` を
**引かない**（`(list|listnum)` だけ）ことと、`@<table>` が `(table|imgtable)` であることを直した。
最初は `//source` も `@<list>` の対象に入れていたが、本家に `SourceIndex` は無いので外した。

## 表の幅: 係数が作業中に変わっていた

`book_mruby3/CLAUDE.md`「紙面幅の制約」から、上限（2 列 0.93 / 3 列 0.90 / 4 列 0.87）と
`l` 列の係数を取って実装した。最初に読んだときの係数は **0.012**、本文幅は 44zw だった。

その値で `book_mruby3` に掛けると 3 本が上限を超えた。

```
references.re:10  mruby_versions（3 列）0.912 > 0.900
vm.re:134         table_ci（3 列）      0.904 > 0.900
extension.re:729  gem_list3（4 列）     0.872 > 0.870
```

超え方が 0.002〜0.012 と小さく、しかも本は `Overfull hbox` 0 でビルドできている。
見積もりが少し厳しすぎるのか、と思って `CLAUDE.md` を読み直したら、値が変わっていた。

```
`l` 列の幅は最長セルの半角換算文字数 × 0.011（全角は 2 文字）で見積もる
（半角 1 文字 ≒ 0.5zw、本文幅 49zw なので 0.5/49 ≒ 0.0102 に余白分を足した値。
 10pt・44zw のときは 0.012 だった）
```

同じ日に著者が本文を 10pt・44zw から 9pt・49zw に変えていた（`cfde212`）。0.011 に直すと
3 本とも上限の下に入り、`table-width` は 0 件になった。**ビルドの事実（`Overfull hbox` 0）と
見積もりが一致した**ので、この係数で合っている。

この経験から `docs/design/thresholds.md` に「本文の大きさを変えたら `charWidth` を直す」と
書き、`.review-assist.json` で上書きできるようにした。

### 外挿したところ

著者が値を与えているのは 2・3・4 列だけである。5 列以上と 1 列は `0.96 - 0.015 × 列数` で
外挿した（3 点をちょうど通る式）。`book_mruby3` の表 82 本はすべて 2〜4 列なので今は使われない。
測っていない数なので、そう書いた。

## コードの行長: 半角換算をやめた

最初は行長も半角換算（全角 2）で数えた。`book_mruby3` で 18 件出た。中を見ると、

```
contents/vm.re:408   struct mrb_jmpbuf c_jmp;   //注：例外処理で使用するsetjmp/longjmp用の…
```

のような**和文コメント入りの C のコード**ばかりで、73 文字・半角換算 85。しかしこの本は
`Overfull hbox` 0 でビルドできている。`CLAUDE.md` 自身も「1 行 83 文字を超えると」（現在は
9pt で「92 文字ほど」）と**文字数**で書いている。`alltt` の和文は半角 2 個分では無い、と
判断して、既定を文字数に変えた。18 件 → 7 件になり、どれも 81〜83 文字で「80 以内」の約束だけを
破っている、という素直な内容になった。

半角換算が要る原稿のために `codeLineWidth: "halfwidth"` は残した。
一方、**表のセルは半角換算のまま**である。`CLAUDE.md` が表については「全角は 2 文字」と
明記しているため。同じ「幅」でも単位が違うので、`thresholds.md` に理由を書いた。

## 規則を地の文だけに当てる

`scope: "prose"` の切り出しで迷った。最初は「ブロックの本体と `#@#` 以外」としたが、それだと
`//tsize[|latex||P{0.3\textwidth}|]` の LaTeX まで地の文になり、`//table[gem_list][…]` の id も
拾ってしまう。かといって `//` の行を丸ごと外すと、**キャプションの中の誤り**（全角数字など）が
見えなくなる。

行に「種別」を付け、`directive` の行だけは**キャプションの引数の範囲**（id の引数と `scale=` を
除いた `[...]`）を地の文として渡すことにした。パーサが `directiveProseSpans` を出し、
診断側が `slice` して正規表現を当てる。診断の桁は `slice.start + m.index` で元の行に戻す。

これが効いているかは、textlint との突き合わせで確かめられた。本のリポジトリには同じ日に
textlint（`prh.yml`）が入っていて、重なる 2 つの規則の件数が一致した。

```
prh.yml のコメント: 全角数字は「2026-09-19 時点で 4 件（opcodes_template.re:58 の「２つ」
「１バイト」、chap3-002-MOVE.re の「２命令」「１命令」）」
この拡張:           rule.fullwidth-digit 4 件、同じ 4 か所
```

## 誤検出の外し方

計画書は「否定先読み、`allowIn` の設定」を挙げている。両方入れた。

旧表記の規則（`R(n)`、`SEQ[`）は、`opcodes_template.re:45` の

```
なお初版（mruby 2.0.0対応）では@<code>{R(n)}、@<code>{Pool(n)}、@<code>{SEQ[n]}という表記を
```

に当たってしまう。`allowIn: ["opcodes_template.re"]` でファイルごと外す案は、あのファイルが
大きい（リファレンスの読み方が全部ある）ので他の誤りが見えなくなる。行に「初版」とあれば
旧表記の説明だ、という読み方にして可変長の後読みで外した。

```json
"pattern": "(?<!初版.*)\\b(R|Pool|Syms)\\([0-9A-Za-z]\\)"
```

`OP_` の規則も同じ形で `@<code>{OP_SEND}` を外している。V8 は可変長の後読みを持っているので
これが書ける（Node 22 で確かめた）。`sliceForScope` が行ごとに切って渡すので、後読みの
`.*` が行をまたぐことはない。

## 捨てた案

* **YAML のパーサを入れる。** `catalog.yml` のために `js-yaml` を足すか迷ったが、読む必要が
  あるのは 4 つのセクションとその下の項目だけなので、40 行で自前で書いた。実行時依存 0 のまま
* **`//terminal` もコードとして行長を見る。** `CLAUDE.md` に「`//terminal` だけは `\seqsplit` で
  自動折り返しされる」とあるので外した
* **`@<code>` の中身を表のセルの幅から割り引く。** 等幅は和文より狭いので理屈はあるが、
  `CLAUDE.md` の式にそんな補正は無い。測っていない補正を入れるのはやめた
* **`vscode-languageclient` で言語サーバにする。** 原稿 2 万行の索引が 25 ms で終わるので、
  別プロセスにする理由が無い
