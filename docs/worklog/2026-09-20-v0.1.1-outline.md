# 2026-09-20 0.1.1 — アウトラインを見出しだけにする

## 出発点

著者から「アウトラインの表示がフラットで項目が多すぎてよく分からない」という指摘があった。
本体のセッションが `contents/vm.re` で確かめたところでは、`buildOutline` は根 1・深さ 5・
118 項目の木をちゃんと返していて、範囲の包含も正しい。つまり「木ができていない」のではなく
「木に見えない」という話である。

原因の候補が 2 つあった。

1. **項目が多すぎる。** 見出しに対してブロック（表・リスト・図・脚注）が多く、
   どの見出しを開いても子がブロックで埋まるので、階層が目に入らない。
2. **VS Code が木を崩している。** `DocumentSymbol` は `selectionRange ⊆ range` と
   子の `range ⊆ 親の range` を前提にしていて、破れた木を平らに並べ直すことがある。

どちらも「フラットに見える」を説明しうるので、両方を潰すことにした。

## 1. 何項目あるのかを数えた

指示には「見出し 44 に対してブロックが 74」とあったが、実際に数えると違った。

```
$ node -e "… ReviewIndex('/home/kishima/book/book_mruby3') …"
headings 66 blocks with id 52 {"footnote":2,"image":16,"table":11,"list":23}
default nodes 66 all blocks nodes 118
```

合計 118 は指示の数と合う。内訳は見出し 66・id 付きブロック 52 で、44/74 ではなかった。
数え方の違い（`= 章` を外した、id の無いブロックも数えた、など）だと思うが、確かめた方を採り、
README・`config.ts` のコメント・CHANGELOG には 66/52/118 と書いた。

いずれにせよ、1 画面に収まらない 118 項目が深さ 5 に散っているので、候補 1 は実在する。
見出しだけにすれば 66 項目になり、ほぼ半分になる。

## 2. 既定を見出しだけにした

`buildOutline(parsed)` に第 2 引数 `{ blocks }` を足し、`blocks` に入っている種類の
ブロックだけを見出しの下に置くようにした（`src/core/outline.ts`）。既定は空配列＝見出しだけ。

設定は `.review-assist.json` の `outline.blocks` で、`"table"` `"list"` `"image"` `"footnote"`
の 4 つから選ぶ（`src/core/config.ts`）。既にある `tableWidth` と同じく入れ子の object にした。
知らない語は黙って落とす。ここは迷った——綴り違いを診断に出す案もあったが、設定ファイルの
検査の仕組みが今は無く（`rules` の `pattern` が壊れていても黙って落ちる）、この 1 項目のために
作るのは釣り合わないと判断した。落とした結果は「その種類が出ない」だけで、気づける。

`blocks` の既定を `[]` にしたのは、著者が「多すぎる」と言っている以上、既定で減る方に倒すため。
「表だけ既定で出す」案も考えたが、根拠になる数が無い（表 11・図 16・リスト 23 のどれを
残すべきかは原稿の読み方次第）ので、全部外して選ばせる形にした。

`name` は `table tbl_mrb_gc` のまま変えていない。`@<table>{tbl_mrb_gc}` と見比べるためで、
指示にもそのままでよいとあった。見出しの `detail` のラベル `{chap_SEND}` も変えていない。

## 3. range の包含 — 実害は無かったが、バグは実在した

候補 2 を確かめるため、5 本のファイル（`contents/vm.re`・`contents/gc.re`・`contents/codegen.re`・
`sub-article/chap3-037-SEND.re`・`opcodes_template.re`）について全ノードを歩いて
`selectionRange ⊆ range` と 子の `range ⊆ 親の range` を検査するスクリプトを書いて回した。

```
contents/vm.re: roots=1 nodes=118 depth=5 violations=0
contents/gc.re: roots=1 nodes=64 depth=5 violations=0
contents/codegen.re: roots=1 nodes=90 depth=5 violations=0
sub-article/chap3-037-SEND.re: roots=1 nodes=14 depth=4 violations=0
opcodes_template.re: roots=1 nodes=15 depth=5 violations=0
```

違反 0。ここで終わりにしてもよかったが、`closeTo` の

```ts
end: { line: Math.max(top.node.span.start.line, endLine), column: 0 }
```

が気になった。見出しの range を「閉じる行の**列 0**」で終わらせている。一方ブロックの range は
`parser.ts:249` で最後の行（`//}`）の**末尾**まで取ってある。ということは、`//}` の次の行が
すぐ見出しなら、子が親から列の分だけはみ出すはずである。作って確かめた。

```
= 章
=== B
//table[t1][c]{
a
//}
== C
x
```

`table t1` の range が `2:0–4:3`、親 `B` が `1:0–4:0`。予想どおりはみ出していた。
`book_mruby3` の原稿では `//}` の後に必ず空行が入るので実害が出ていなかっただけで、
バグは実在した。ファイルの最後の行が `//}` の場合も同じ（根が列 0 で閉じる）。

直しは、見出しの終わりを「その行の末尾」にする 1 行。`parsed.lines[line]?.length ?? 0` を使う。

```ts
const endOfLine = (line: number): Span['end'] => ({ line, column: parsed.lines[line]?.length ?? 0 });
```

`//}` の末尾はその行の長さと等しいので、これで必ず親に収まる。既存の
「見出しの範囲は次の同位以上の見出しの手前まで」のテストは `end.line` しか見ていないので通る。

この直しが効いていることは、直す前の形に戻して確かめた。

```
$ (column: 0 に戻して) npm test
not ok 30 - buildOutline: //} の直後が見出しでも子が親からはみ出さない
not ok 31 - buildOutline: 最後の行が //} でも根からはみ出さない
# pass 83
# fail 2
```

戻すと落ちる。テストが仕事をしている。

## 4. テスト

検査そのものは `test/helper.js` の `checkContainment` に置いた（`*.test.js` ではないので
`node --test test/*.test.js` は拾わない）。同じものを 2 つのテストファイルから使う。

* `test/misc.test.js` — 既定では見出しだけ、`blocks` に入れた種類だけ出る、`//}` の直後が
  見出しの場合、最後の行が `//}` の場合、`loadConfig` が知らない種類を落とすこと
* `test/book_mruby3.test.js` — 上の 5 本について、`blocks` が空のときと全部のときの両方で
  包含が成り立つこと。あわせて「既定の木のノード数 == 見出しの数」「ブロックを入れると増える」
  「見出しだけでも深さ > 1」

`blocks` を全部入れた場合も検査しているのは、設定で出す人がいる以上そちらでも崩れては困るため。

```
$ npm test
# tests 85
# pass 85
# fail 0
```

0.1.0 の 76 件から 9 件増えた。

## 残っている不確かさ

**VS Code で実際にどう見えるかは確かめていない。** この環境には Extension Development Host が
無く、0.1.0 のときと同じく `src/core/` しか回せない。「既定で 66 項目になる」ことと
「range の包含が成り立つ」ことは測ったが、それで著者の画面のアウトラインが木に見えるように
なったかどうかは、著者が新しい `.vsix` を入れて見るまで分からない。

もし見出しだけにしてもまだフラットに見えるなら、原因は残りの候補——たとえば VS Code の
アウトラインビューの並べ替え設定（`outline.sortBy` が `name` や `type` になっていると
階層が崩れて見える）や、ビューが「Follow Cursor」で一部だけ開いている——の側にある。
その場合は設定を見てもらうのが先で、拡張側で直すものではない。
